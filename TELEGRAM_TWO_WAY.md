# Gortenzium ↔ «Гортензия — Мой сад» — импорт фото из Telegram (v1.9)

## Что реально происходит

**Из приложения в Telegram (v1.8):** владелец фото нажимает «В Telegram» и вручную выбирает получателя. Это системная отправка Android, а не автоматическая запись в канал.

**Из канала в приложение (v1.9):** администратор размещает фотографию в **публичном** канале `@Gortenzium` и добавляет к подписи `#в_альбом`. При настроенном боте Telegram отправляет `channel_post` на Supabase Edge Function. Функция проверяет секрет webhook, числовой ID и username канала, забирает уменьшенный JPEG через Bot API и сохраняет в отдельном публичном бакете. Строка в `telegram_gallery` становится доступна во вкладке приложения «Альбом → Gortenzium»; нажатие открывает исходный пост в Telegram. Личный фотодневник пользователя **не** импортируется и **не** публикуется сам по себе.

**Важно:** без следующих действий владельца канала/облачного проекта импорт **не работает**. В ZIP — код и инструкции, но нет живого бота, токенов, сервера и подключённой базы.

## Настройка владельцем, один раз

1. Подключите общий проект Supabase согласно `supabase/SETUP.md` и убедитесь, что APK собран с его `SUPABASE_URL` и `SUPABASE_ANON_KEY` (только публичный ключ). Если этот проект уже создан, **не** запускайте повторно `setup.sql`.
2. В SQL Editor того же проекта выполните `supabase/telegram_migration.sql`. Он добавит **отдельный** публичный бакет для опубликованных постов канала и таблицу `telegram_gallery`. Частные фотографии участников в бакете `garden-photos` останутся частными.
3. Создайте отдельного Telegram-бота через официальный BotFather. Добавьте бота администратором **вашего** канала `@Gortenzium` с достаточными правами для получения `channel_post`. При настройке проверьте числовой ID канала через метод Bot API `getChat` с параметром `chat_id=@Gortenzium` (ответ содержит `result.id`; начинается с `-100…`). Убедитесь, что вы действительно администратор этого канала. Сообщать токен бота мне или добавлять его в Android/GitHub **не нужно**.
4. В Supabase Edge Functions → Secrets (или через безопасный `.env` вне GitHub) установите `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` (случайные ≥32 символов из `[A-Za-z0-9_-]`), `TELEGRAM_CHANNEL_ID` (точный `result.id`), а также серверный ключ с правами `service_role` — если `SUPABASE_SERVICE_ROLE_KEY` не предоставлен средой, задайте `GARDEN_SERVER_KEY` в секретах Supabase. **Никогда** не помещайте эти значения в `BuildConfig`, `supabase.properties`, публичный репозиторий и ответы чата. В канале не публикуйте сведения для входа.
5. Разверните функцию `gortenzium-webhook` через Supabase CLI, используя `supabase/config.toml`; в нём `verify_jwt=false` **только для этой функции**, поскольку Telegram не отправляет JWT Supabase. Запрос защищён отдельным `X-Telegram-Bot-Api-Secret-Token` и привязкой к каналу. Для Supabase CLI команда из корня проекта: `supabase functions deploy gortenzium-webhook --project-ref YOUR_PROJECT_REF --no-verify-jwt` (при необходимости сначала `supabase login`). `YOUR_PROJECT_REF` — идентификатор вашего проекта, не секретный токен.
6. С помощью **серверного** запроса Bot API `setWebhook` задайте URL `https://YOUR_PROJECT_REF.supabase.co/functions/v1/gortenzium-webhook`, `secret_token` с тем же секретом, `allowed_updates=["channel_post","edited_channel_post"]`, `drop_pending_updates=true` для начала с новых сообщений. Проверьте результат вызова и `getWebhookInfo`: должно быть указано правильное `url`, без ошибок доставки. **Не вставляйте бот-токен в открытые веб-формы, логи или Github Issue.**
7. После этого сделайте новый пост с фото в `@Gortenzium` и подписью, например: `Limelight в сентябре #в_альбом`. Откройте приложение → «Альбом» → «Обновить альбом» → фильтр «Gortenzium». Откройте исходный пост кнопкой под фото.

## Правила публикаций и ограничения

- В приложение **автоматически попадают только новые фото-посты публичного канала с `#в_альбом`**, опубликованные после подключения бота/webhook. Сообщения подписчиков, комментарии в группе, произвольные фотографии канала, старые посты, тексты без фото и личные сообщения не импортируются.
- Администратор канала должен проверять снимок до публикации: только изображения растений, согласие автора на повторный показ в приложении, отсутствие людей, персональных данных, адресов, номеров, нежелательного контента и указаний геопозиции в подписи. Поскольку фото канала уже общедоступны, их зеркальная копия хранится в отдельном **public** бакете Supabase. Снимки из личного приложения сами туда не попадают.
- Исправление подписи `edited_channel_post` обновляет текст; удаление метки у зеркального поста при редактировании удалит копию. **Удаление самого поста из Telegram не вызывает Bot API-событие удаления**: администратору нужно отдельно удалить строку `telegram_gallery` и файл `gortenzium-channel/Gortenzium/ID.jpg` через Supabase Dashboard. Сделайте это также при запросе автора на удаление. Удаление из приложения не удаляет пост Telegram.
- Не обещается двусторонняя синхронизация личного сада с аккаунтом Telegram: это две независимые ленты, связанные публикацией по явному действию, без доступа к перепискам и контактам.
- Сорт из текста подписи не определяется автоматически, чтобы не выдавать неверную идентификацию. Фото в ленте помечено «Из канала Gortenzium»; сорт остаётся неуказанным, если запись не является постом пользователя приложения.
- Для установки из ZIP требуется сборка APK через GitHub Actions; серверный импорт отдельно нужно развернуть в Supabase. Локальные тесты не равны успешному приёму настоящего webhook.
