# «Гортензия — Мой сад» v2.1: существующие темы группы Telegram ↔ сорта

## Важное различие

`https://t.me/Gortenzium` может быть каналом или группой. **Обычный канал не поддерживает форумные темы**: они принадлежат супергруппе, которая может быть связана с каналом. Узнайте, в какой конкретно супергруппе сейчас находятся ваши темы сортов. Для настоящей интеграции нужен её `chat.id`, а не ID канала и не только публичное имя. Без реального доступа к вашей группе этот архив не содержит точных существующих `chat_id`/`message_thread_id`; их привязывает администратор внутри каждой темы.

## Порядок запуска

1. Если база ещё не настроена, сначала выполните `supabase/setup.sql`, `supabase/telegram_migration.sql`, `supabase/variety_migration.sql`, `supabase/varieties_seed.sql` по прежним инструкциям. В существующей базе эти исходные миграции не запускайте без проверки. Затем отдельно выполните `supabase/topic_migration.sql` в SQL Editor проекта Supabase. Таблицы `gortenzium_topics` и `telegram_topic_gallery` доступны на чтение и закрыты для клиентской записи; только сервер с service-role записывает фото и назначения.
2. Добавьте бота **администратором именно той супергруппы**, где находятся темы сортов. Для чтения сообщений и ответов ему нужен доступ к сообщениям группы и возможность писать в темы; дополнительно настройте BotFather /setprivacy при необходимости. Боту не требуется право удалять пользовательские сообщения или создавать темы. Не предоставляйте лишние полномочия.
3. Получите числовой ID **этой группы** `-100…` через Bot API `getChat` для публичной группы или через доверенный просмотр обновления группы при временно отключённом webhook (`getUpdates` до регистрации webhook). Это не ID @Gortenzium-канала, если темы у связанной группы. Токен храните только у себя/в Supabase secrets.
4. Установите серверные переменные: `TELEGRAM_FORUM_CHAT_ID` (ID супергруппы с темами), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` (случайная длинная строка, не менее 32 знаков), `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`. Не помещайте их в GitHub или APK. Для Android нужны только публичные `SUPABASE_URL`, `SUPABASE_ANON_KEY`.
5. Разверните `supabase/functions/gortenzium-webhook` заново. Настройте для бота `setWebhook` на эту функцию с `secret_token`, `allowed_updates=["message","edited_message"]`. **Не направляйте один и тот же бот одновременно на старый обработчик канальных публикаций:** Telegram принимает один webhook для бота. Для одновременно работающего канала и форумной группы требуется общий маршрутизатор, который обрабатывает оба типа обновлений.
6. **В существующей теме сорта** отправьте от имени администратора команду `/bind limelight` (подставьте нужный `variety_key` из `supabase/varieties_seed.sql`). Например, в теме «Самарская Лидия» отправьте `/bind самарская_лидия`. Бот проверит право администратора и ответит в этой же теме. Он сохранит её **фактические** `chat_id + message_thread_id`, а не догадается о сорте по тексту, совпадению названия или посту в канале.
7. Повторите для тем остальных сортов. У одной темы может быть только один сорт, и один сорт в этой группе может быть привязан только к одной теме. Перепривязка темы с уже загруженными фото автоматически заблокирована, чтобы не потерять происхождение фотографий.
8. От имени **неанонимного администратора** опубликуйте тестовое фото прямо в уже привязанной теме с подписью `#в_альбом`. Снимок появится только в одноимённом сортовом альбоме приложения, без добавления `#сорт_...`. Фото из чужой темы, другого чата, сообщения без отметки и обычные фото пользователей бот не импортирует. Проверьте две темы (например, Limelight и Bobo) на отсутствие пересечения.
9. Пересоберите APK с доступом к обновлённому Supabase. В приложении откройте «Альбом → сорт». Кнопка «Открыть тему этого сорта в Telegram» ведёт в **реальную связанную тему**, а кнопка под импортированным фото — к сообщению в ней. Если группа закрытая, пользователь должен быть её участником.

## Обратное направление

Фото, отправленные из Android в общий альбом, **сначала остаются на проверке в Supabase и не публикуются ботом в Telegram автоматически**. Для ручной отправки в тему откройте по кнопке нужную тему в Telegram и отправьте фото через Android (после согласия автора на такую публикацию). В приложении не производится скрытая пересылка личных дневников. Для серверной автопубликации по итогам модерации нужен отдельный поток с явным согласием пользователя на публикацию в Telegram и подтверждением администратора.

## Не охватывает этот релиз

- Прошлые сообщения и всю историю тем: Bot API webhook обрабатывает только новые/отредактированные сообщения, доступные боту после подключения.
- Удаление поста в Telegram: обычного события удаления у Bot API нет, удаление зеркальной копии администратор делает отдельно.
- Анонимные сообщения администраторов: они не проходят проверку персонального статуса. Используйте обычную учётную запись администратора для публикации с `#в_альбом`.
- Сохранение форумной структуры, если там на самом деле *не* темы супергруппы, а обсуждения под постами канала: сперва проверьте реальную конфигурацию Gortenzium.
